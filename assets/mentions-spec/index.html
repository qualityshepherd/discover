Mentions, shared

A tiny spec for blog indexes to share who linked to whom. One JSON file. No accounts, no pings, no endpoints to run. Version 1.

Discover publishes one at /api/mentions.json. Anyone can read it. Anyone can publish their own.

The file

{
  "version": 1,
  "updated": "2026-11-23T19:51:17.016Z",
  "days": 30,
  "spec": "https://discover.brine.dev/mentions-spec",
  "mentions": [
    {
      "post": "https://brine.dev/posts/blogroll-manuelmorealecom",
      "title": "Blogroll: manuelmoreale.com",
      "date": "2026-11-23T16:29:44.000Z",
      "links": ["https://manuelmoreale.com"]
    }
  ]
}
fieldwhat it is
versionAlways 1 for now. Bumped only for breaking changes.
updatedWhen the file was built, like 2026-11-23T19:51:17Z.
daysHow far back the file goes. 30 is a good default.
specOptional. A link to this page.
postThe post that did the linking.
titleIts title. Can be empty.
dateWhen it was published, like 2026-11-20T18:16:29Z, or null if unknown. Never a guess.
linksEvery link in that post to another site. Full URLs.

Serve it with Access-Control-Allow-Origin: * so browsers can read it too. Caching is fine. Ignore fields you don't know; new ones may appear without a version bump.

Two rules

1. First-hand only. List links from posts you host or fetch yourself. Never republish mentions you read in someone else's file. Every claim stays one hop from a real post, so junk can't be laundered through a chain of peers.

2. The receiver verifies. A file is a claim about where to look, not proof. Before showing a mention, fetch the post and check the link is really there. A peer that lies just produces claims that fail.

Publishing: the easy half

If you host or index blog posts, you already have this data. For each post from the last days, collect the links that point to other sites. Write the file. Serve it. That's the whole job. Publishing asks nothing of anyone, and trusts no one.

Reading other files

  1. Pick whose files you read. That's your call, not theirs.
  2. Keep only links to blogs you care about. Drop the rest.
  3. Verify each one (rule 2).
  4. Remember where each mention came from, so you can drop a peer later and its mentions with it.
  5. Show a title and a link back. Don't copy their words; the post belongs to its author.

Trust is yours

Verifying proves a link exists. It doesn't prove the blog is worth hearing from. That part is curation, and only you can decide how much of someone else's you'll take. A simple way to think about it, per peer:

  • auto: verified mentions show up right away. For peers whose curation you'd vouch for.
  • review: verified mentions wait for you to approve them. A good start for anyone new.
  • off: you don't read that file at all.

What this isn't

It isn't webmentions: nobody sends you anything, you go and read files you chose. It isn't comments: a mention is a post someone wrote on their own site, under their own name, and it links back instead of being copied.
